# Goals and decisions

The owner's goals and decisions. **This document wins** wherever another document seems to disagree.
How each one is built: [architecture](architecture.md) and [`apps/DESIGN.md`](../apps/DESIGN.md).

## 1. Goals

Set by the project owner. Every design decision is checked against these.

1. **Just works, never breaks.**
2. **Updates are a simple downloadable file** that users apply.
3. **One OS for development (coding), gaming (depending on the hardware) and general use.**
4. **One ISO.** At install time users pick a profile (dev, game, general, or a mix such as dev+game) or let the installer choose automatically. *(Since D26 there is nothing to pick: everything is on for everyone.)*
5. **One desktop environment, no choice:** popular, customizable, stable and continuously updated: **KDE Plasma**.
6. **Works with Microsoft Secure Boot**: out of the box, during installation, or by a setup step after installation.
7. **The developer can ship an update that changes anything, at any time.** Btrfs (not ext4) avoids partitioning hassle.
8. **No release cycles.** A rolling base avoids Fedora-style 6-month upgrades and end-of-life dates. Arch is not a goal in itself; it was chosen because it fits. Whether a base distribution "supports" Asima OS does not matter.
9. **x86_64 only.**
10. **Reset works like Android's factory reset: it keeps nothing.**
11. **The base contains no app that also exists as a sandboxed app** (Flatpak, Snap, AppImage), and no sandboxed app is preinstalled, **except KDE Plasma and a standard set of KDE apps** (see D4). Since D28: only what must run natively is in the system at all.
